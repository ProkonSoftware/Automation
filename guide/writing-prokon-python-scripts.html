Writing PROKON-Python scripts

This guide explains the few ideas every PROKON script uses. The real teaching material is the examples folder: more than 150 working scripts covering every engine. Read this page once, then learn from the examples.

Scripts work the same way in Spyder, in VS Code and in the Automation Host. Install one of them first (see the guides above).

1. One call per design

import prokon.v5

answer = prokon.v5.beam_section.analyse(
    design_code="BS8110 - 1997",
    m=200, v=100,              # moment (kNm) and shear (kN)
    bw=300, h=500,             # width and depth (mm)
    dc_t=40, dc_b=40, dc_s=40, # covers to the bar centres (mm)
    fcu=30, fy=450, fyv=450,   # material strengths (MPa)
)

result = answer["result"]
print(result["mu"])            # moment capacity: 295.18197048179997

That is the whole pattern: prokon.v5.<engine>.analyse(...) with named inputs. Each call runs the same engine as the PROKON desktop program, so the numbers are the desktop's numbers.

2. What comes back

analyse() returns a Python dictionary describing the whole run. The parts you will use:

KeyWhat it holds
answer["result"]The engineering results, as a dictionary (for example "mu", "ast"). Numbers are at full precision, not rounded as on a calcsheet. Format them yourself when printing: f"{result['mu']:.1f}".
answer["ok"]True when the engine produced an answer.
answer["warnings"]A list of messages from the engine: "this answered, but read this before you use it".
A design that fails its checks is still an answer. If the section is inadequate, ok is still True and the results tell you what failed. Only "no answer could be produced at all" counts as an error.

3. Finding the right input names

Inputs use the short engineering names from the desktop programs (fcu, bw, dc_t). Everything is metric: mm, MPa, kN, kNm. Three ways to look them up:

  • Ask Python: help(prokon.v5.beam_section.analyse) lists every input, which ones are required, and what each means.
  • Allowed text values are listed on the engine module, for example prokon.v5.beam_section.DESIGN_CODE_VALUES.
  • Copy a quickstart. Each engine has one in examples/quickstarts/, with every input commented.

Text values must match exactly, including capitals and spaces: "BS8110 - 1997", not "bs8110 - 1997". Optional inputs you leave out get the engine's own default. A required input you leave out stops the call with a normal Python TypeError naming it.

4. When something goes wrong

When the engine refuses a request, the call raises prokon.v5.ProkonError, which says what happened and often how to fix it:

try:
    answer = prokon.v5.beam_section.analyse(design_code="bs8110 - 1997", ...)
except prokon.v5.ProkonError as e:
    print(e.category)   # "invalid_input"
    print(e.message)    # "bs8110 - 1997" is not one of the values "design_code" accepts.
    print(e.hints)      # the full list of allowed design codes

Two categories are worth telling apart:

  • invalid_input: the request itself is wrong (a typo, a value out of range). Fix the script.
  • no_solution: the request was fine, but no answer exists for it. In a search loop this is a normal result to skip past, not a bug.

Each call is allowed 120 seconds by default. Change it with prokon.v5.timeout_seconds = 300. The examples/going-deeper/ folder shows full error handling for every engine.

5. The real power: loops, tables and charts

A script is ordinary Python, so you can do what the desktop program alone cannot: run a hundred variations, put the results in a table, and plot them.

import pandas as pd
import prokon.v5

rows = []
for h in [400, 450, 500, 550, 600]:
    answer = prokon.v5.beam_section.analyse(
        design_code="BS8110 - 1997",
        m=200, v=100, bw=300, h=h,
        dc_t=40, dc_b=40, dc_s=40,
        fcu=30, fy=450, fyv=450,
    )
    result = answer["result"]
    rows.append({"h (mm)": h, "Mu (kNm)": result["mu"], "As (mm2)": result["ast"]})

table = pd.DataFrame(rows)
print(table.round(1))

You can also pass one engine's result straight into the next: a beam's support reactions become a column's loads, which become a footing's loads. The examples/workflows/ folder does exactly this.

6. Working with desktop files

Each engine can also read and write the desktop program's own data files:

  • load_file(path=...) reads a desktop file. Its ["result"]["inputs"] can go straight back into analyse().
  • save_file(..., path=...) takes the same inputs as analyse() and writes a file you can open in the desktop program.
loaded = prokon.v5.beam_section.load_file(path="RectangularBeamExample-W5.3.05.C22")
inputs = loaded["result"]["inputs"]
result = prokon.v5.beam_section.analyse(**inputs)["result"]

The examples/built-in-desktop-examples/ folder runs every desktop Examples-menu file this way and compares each result with the desktop's own calcsheet.

7. A tour of the examples

Every script runs as it is and prints its results. Each opens with a header saying what it shows and how its numbers were checked. The examples use only Python's standard library plus numpy, pandas, matplotlib and openpyxl.
